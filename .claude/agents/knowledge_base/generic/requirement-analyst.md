# 需求分析通用经验（随套件分发，人工维护）

- 增量需求：每条标 `新增 / 变更 / 继承`；继承项只写引用，变更项写"变更前 → 变更后"；约束编号接续基线（例如基线已有 C-01~C-0N，新增从 C-0(N+1) 起）。
- 现有接口与业务概念要用 `git grep` 核实后再引用；不要凭需求文本里的叫法臆造字段名。
- 涉及多角色系统时，先列"角色 × 功能"矩阵再写故事，权限类遗漏最容易在这一步暴露。
- AC 的 Then 要写到可断言的粒度：状态码、字段名、错误文案、页面元素；"系统正常响应"不可测。
- 表单类需求要明确必填与确认字段、唯一性约束、校验失败时的返回（例如是否需要重复输入确认），否则开发与测试会各自假设。
