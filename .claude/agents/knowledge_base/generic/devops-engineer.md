# 运维通用经验（随套件分发，人工维护）

## 回滚
- 回滚不得破坏目标机本地状态：`git reset --hard` 会冲掉已跟踪文件的本地修改，`git stash` 会把本地配置藏起来导致服务起不来，`git clean` 会删掉未入库的配置/数据。
- 首选"源头 revert → 正常部署流程"，目标机始终与远端一致，下次部署不冲突。
- 紧急止血用"就地恢复修改过的文件"时：文件列表只取修改项（`--diff-filter=M`），本次新增的文件不要列入（旧版本中不存在会报错；它们不被旧代码引用，保留无害）；事后必须收尾，让工作树回到与远端一致的干净状态。
- 数据迁移不可简单逆向：写明逆向命令与数据风险，标 MANUAL_ROLLBACK_REQUIRED。

## 远端命令
- `ssh host '<命令>'` 单引号中的 `$VAR` 在远端展开，通常为空。要用本地变量时用双引号或先 echo 完整命令核对。
- 典型后果：`ssh <host> 'git checkout $REF -- <files>'` 中 `$REF` 在远端为空 → 变成从索引恢复，拿回的仍是新代码，回滚静默失效。
- 执行回滚前核验变量：锚点是完整哈希且 `git cat-file -t` 为 `commit`；执行后检查恢复的文件确实变化。

## CI/CD
- 流水线顺序：Lint/安全扫描 → 单元 → 集成 → 构建 → 打包/制品 → 部署 → 部署后冒烟 → E2E；冒烟/E2E 只在部署成功后运行，报告作为 artifact 上传。
- 集成测试阶段要指定测试专用配置（如测试用 settings / profile / 环境变量），否则会读到开发/生产配置。
- 冒烟脚本中会写库的唯一字段必须动态生成。
- 只改文档/agent 配置的提交可以在 CI 中排除（paths-ignore），节省资源。

## 部署
- pull 前对比本次变更文件与目标机本地修改的交集；有交集就停下上报。
- 小内存目标机上部署后关注 OOM：异步 worker 并发、批处理大小、模型加载。
- systemd unit、env 模板、检查清单等非代码交付物与设计文档的漂移不会被测试发现：写部署计划时逐条比对二进制路径、端口、工作目录与多处重复的数值（如内存上限同时出现在 unit 和 env 中）。
